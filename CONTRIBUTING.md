# Как мы работаем с git: шпаргалка для команды

Короткая инструкция для тех, кто с git почти не работал. Если что-то сломалось — не паникуйте и не делайте `git push --force`; напишите в чат команды.

## Главная идея за 30 секунд

- **main** — основная ветка. В ней всегда лежит рабочий код. Напрямую в неё никто не пишет.
- Каждая задача делается в **своей ветке** — это ваша личная копия кода, где можно ломать что угодно.
- Когда задача готова, вы открываете **Pull Request (PR)** — просьбу «влейте мои изменения в main».
- **CI** (автопроверка) сам собирает код и запускает тесты. Результат — зелёная галочка или красный крестик в PR.
- Другой разработчик смотрит код и нажимает **Approve** (одобрить).
- Зелёный CI + одно одобрение → автор нажимает **Merge** — код попадает в main.

## Один раз: подготовка

1. Примите приглашение в репозиторий (письмо от GitHub или https://github.com/notifications).
2. Установите git: https://git-scm.com/downloads (на Windows ставьте вместе с Git Bash).
3. Представьтесь git'у (один раз на компьютер):
   ```bash
   git config --global user.name "Ваше Имя"
   git config --global user.email "почта@от.github"
   ```
4. Скачайте репозиторий:
   ```bash
   git clone https://github.com/alex-dnd/virtual-machine-jvm.git
   cd virtual-machine-jvm
   ```
   Если спросит логин/пароль: вместо пароля нужен токен (GitHub → Settings → Developer settings → Personal access tokens) или проще — установите GitHub CLI (https://cli.github.com) и выполните `gh auth login`.

## Каждая задача: 6 шагов

```bash
# 1. Взять свежий main
git switch main
git pull

# 2. Создать ветку под задачу (номер задачи + пара слов)
git switch -c feature/17-utf8

# 3. Писать код... затем посмотреть, что изменилось
git status

# 4. Сохранить снимок (коммит). Делайте коммиты часто, маленькими кусками
git add src/lexer.cpp tests/lexer_utf8_test.cpp
git commit -m "Лексер: декодирование UTF-8 и BOM (#17)"

# 5. Отправить ветку на GitHub
git push -u origin feature/17-utf8     # первый раз
git push                               # дальше просто так
```

**6. Открыть PR.** После `git push` GitHub покажет ссылку — откройте её, или зайдите в репозиторий и нажмите жёлтую кнопку «Compare & pull request».
- Заголовок: что сделано. В описании напишите `Closes #17` — задача сама закроется после слияния.
- Справа в Reviewers выберите другого разработчика.
- Или из консоли: `gh pr create --fill`.

## Ревью: что делает проверяющий

1. Открыть PR → вкладка **Files changed**.
2. Если есть вопрос — нажать «+» у строки и написать комментарий.
3. Кнопка **Review changes** → **Approve** (всё хорошо) или **Request changes** (надо поправить).

Автор правит код в той же ветке, делает `git add`, `git commit`, `git push` — PR обновится сам.

## Слияние

Когда в PR зелёная галочка CI и есть Approve, автор нажимает **Merge pull request** → **Confirm**. Потом можно нажать «Delete branch».

## Если main ушёл вперёд (пока вы работали)

```bash
git switch main
git pull
git switch feature/17-utf8
git merge main
```

Если git пишет **CONFLICT** — значит, вы и кто-то другой поменяли одни и те же строки.
1. Откройте файл: там будут метки `<<<<<<<`, `=======`, `>>>>>>>`.
2. Оставьте правильный вариант (часто — оба куска), удалите метки.
3. `git add <файл>` → `git commit` → `git push`.

Не уверены — напишите в чат, разберём вместе. Именно поэтому у каждого свой раздел в `lexer.cpp`: так конфликтов почти не будет.

## Красный крестик CI — что делать

Нажмите на крестик → **Details** → прокрутите лог до первой ошибки. Обычно это:
- код не компилируется (у нас предупреждения тоже считаются ошибками — `-Werror`);
- упал тест;
- санитайзер (ASan/UBSan) нашёл выход за границу массива или неопределённое поведение.

Исправьте локально, закоммитьте, запушьте — CI перезапустится сам.

## Чего не делать

- Не коммитить прямо в main.
- Не использовать `git push --force` (может стереть чужую работу).
- Не менять публичный интерфейс `include/egg/lexer.h` без согласия Саши.
- Не коммитить папку сборки (`build/`) и бинарники.

## Мини-словарь

| Слово | Что значит |
|---|---|
| commit | сохранённый снимок изменений с подписью |
| branch (ветка) | отдельная линия работы, не мешает другим |
| push / pull | отправить на GitHub / забрать с GitHub |
| PR (pull request) | просьба влить ветку в main + место для обсуждения |
| review / Approve | проверка кода коллегой / «одобряю» |
| merge | слить ветку в main |
| CI | автоматическая сборка и тесты на каждый PR |
| conflict | два человека поменяли одно место — git просит выбрать |
