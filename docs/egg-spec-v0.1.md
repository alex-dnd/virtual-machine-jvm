# Egg 0.1 — спецификация языка (редакция с семантикой значений)

Источник программы — один UTF-8 файл `.egg` (кодировка файла не определяет набор символов значений `char` и строк: для них используется ASCII). Точка входа — `fn main()` без параметров и результата (явное `-> void` допустимо). Явный вызов `main` — статическая ошибка. Описание определяет семантику языка; формат байткода и устройство ВМ остаются за пределами спецификации.

## 1. Лексика

Регистр значим. Идентификатор: `[A-Za-z_][A-Za-z0-9_]*`. Snake_case — соглашение. Пробел, табуляция, LF и CRLF разделяют токены; перенос строки не завершает оператор. BOM допустим только в начале файла. Позиции в диагностике нумеруются с 1: столбец считается в кодовых точках, табуляция занимает одну позицию, CRLF — один перенос.

Комментарий `//` продолжается до переноса строки или EOF. Внутри литералов эта последовательность — текст.

Ключевые слова:

```text
class constructor fn int bool char vector void
if else while break continue return
this true false
```

`main`, `print`, `println`, `read_int`, `read_line`, `exit` — зарезервированные встроенные имена; пользовательским разрешено только объявление точки входа `main`. `size`, `empty`, `push`, `pop`, `remove`, `clear` — обычные идентификаторы со специальным значением у вектора.

Знаки:

```text
{ } ( ) [ ] < > , ; . = + - * / % !
-> == != <= >= && ||
```

Лексер выбирает самый длинный допустимый знак; `//` имеет приоритет над `/`. В `vector<vector<int>>` два закрывающих `>` — отдельные токены. `a--b` разбирается как `a - -b`, `!!x` — как два префиксных отрицания.

Целый литерал: `[0-9]+`, десятичный; ведущие нули разрешены. Буква или `_` непосредственно после цифр вызывает лексическую ошибку. `int` — знаковый 64-битный тип с диапазоном −9223372036854775808…9223372036854775807. Величина 9223372036854775808 разрешена только как непосредственный операнд унарного минуса; остальные выходы литералов за диапазон — ошибка компиляции.

Символьный литерал заключён в `'`, текстовый — в `"`. `char` занимает **1 байт** и содержит символ ASCII с кодом **0…127** (0x00…0x7F). В исходном тексте литерала напрямую допустимы печатные ASCII-символы (0x20…0x7E); остальные записываются escape-последовательностями: `\n`, `\r`, `\t`, `\0`, `\\`, `\'`, `\"`, `\xHH` (ровно две шестнадцатеричные цифры, значение не более 0x7F). После обработки escape символьный литерал должен содержать ровно один символ ASCII; текстовый — произвольное число таких символов. Не-ASCII символы в литералах, неверные escape, незакрытые литералы и физические переносы в них — лексические ошибки. Файл исходного кода остаётся UTF-8: не-ASCII текст разрешён в комментариях, но не в литералах.

## 2. Грамматика EBNF

`{ X }` — повторение, `[ X ]` — необязательная часть. IDENT, INTEGER, CHAR, TEXT — токены лексера. Семантические ограничения применяются после разбора.

```ebnf
program       = { class_decl | function }, EOF ;
class_decl    = "class", IDENT, "{", { field | constructor | function }, "}" ;
field         = type, IDENT, ";" ;
constructor   = "constructor", "(", [ parameters ], ")", block ;
function      = "fn", IDENT, "(", [ parameters ], ")",
                [ "->", (type | "void") ], block ;
parameters    = type, IDENT, { ",", type, IDENT } ;
type          = "int" | "bool" | "char" | IDENT
              | "vector", "<", type, ">" ;
block         = "{", { statement }, "}" ;
statement     = block | var_decl | if_stmt | while_stmt
              | "break", ";" | "continue", ";"
              | "return", [ expression ], ";"
              | expression, [ "=", expression ], ";" ;
var_decl      = type, IDENT, [ "=", expression ], ";" ;
if_stmt       = "if", "(", expression, ")", block,
                [ "else", (block | if_stmt) ] ;
while_stmt    = "while", "(", expression, ")", block ;
expression    = logical_or ;
logical_or    = logical_and, { "||", logical_and } ;
logical_and   = equality, { "&&", equality } ;
equality      = relation, [ ("==" | "!="), relation ] ;
relation      = additive, [ ("<" | "<=" | ">" | ">="), additive ] ;
additive      = product, { ("+" | "-"), product } ;
product       = unary, { ("*" | "/" | "%"), unary } ;
unary         = ("!" | "-"), unary | postfix ;
postfix       = primary, { ".", IDENT | "[", expression, "]"
                         | "(", [ arguments ], ")" } ;
primary       = INTEGER | CHAR | TEXT | "true" | "false"
              | IDENT | "this" | "(", expression, ")"
              | "vector", "<", type, ">", "[", [ arguments ], "]" ;
arguments     = expression, { ",", expression } ;
```

`type` с IDENT должен разрешаться в имя класса. `void` допустим только как возвращаемый тип. Глобальные функции и методы имеют одинаковый синтаксис, но методы объявляются внутри класса. Вызов `C(args)` для имени класса создаёт значение класса и вызывает его конструктор. При разборе `IDENT(...)` синтаксическая форма одинакова для конструирования и вызова функции, а различие устанавливается разрешением имени: имя класса означает конструирование, имя функции — вызов. В `vector<int> xs;` после типа идёт идентификатор переменной; в `vector<int>[1, 2]` после типа идёт `[` литерала.

При `=` слева допускается только *место хранения* (переменная, её поле или элемент вектора, возможно с дополнительными полями/индексами и скобками). Присваивание — оператор, а не выражение. Без `=` выражение-оператор должно оканчиваться вызовом функции/метода либо созданием значения `C(...)`. Встроенная операция `exit("message")` также является вызовом-оператором. Нельзя вызвать произвольное значение как функцию: `make().run()` допустимо, `make()()` — нет.

Пустые блоки допустимы. Завершающие запятые и пустые операторы не допускаются. Объявления полей состоят из типа и имени; их начальные значения задаются при создании объекта.

## 3. Типы и семантика значений

**Все типы Egg имеют семантику значений.** Присваивание, инициализация из другого значения, передача аргумента и возврат результата создают независимое значение соответствующего типа. Пользовательские ссылки, указатели и передача по ссылке не являются частью этой модели.

| Тип | Значение по умолчанию | Копирование |
|---|---|---|
| `int` | `0` | По значению |
| `bool` | `false` | По значению |
| `char` | ASCII NUL (0x00) | По значению |
| `vector<T>` | Пустой вектор | Независимый вектор, рекурсивное копирование элементов |
| Класс `C` | Результат конструктора `C()` | Поэлементное копирование полей |

Типизация статическая, неявных преобразований нет. Типы переменных, параметров и полей указываются явно. Тип любого литерала вектора указан в его записи: `vector<int>[1, 2]`. Текстовый литерал имеет тип `vector<char>` и создаёт изменяемый вектор однобайтовых символов ASCII. Вложенные векторы допустимы. Элементы `vector<T>` имеют тип `T`; типы векторов инвариантны.

Копирование пользовательского объекта последовательно копирует его поля по правилам их типов. Копирование не вызывает конструктор пользователя; пользовательского copy-конструктора нет. При копировании вектора создаются независимые элементы; изменения любой копии не отражаются в другой. При присваивании вычисленное правое значение должно быть сохранено до замены старого содержимого, в том числе при самоприсваивании.

```egg
class Counter {
    int value;
}

fn main() {
    Counter a = Counter();
    Counter b = a;
    b.value = 42;
    println(a.value); // 0

    vector<int> xs = vector<int>[1, 2];
    vector<int> ys = xs;
    ys.push(3);
    println(xs.size); // 2
}
```

Для значения класса без явного инициализатора требуется конструктор без параметров. Если конструктор у класса объявлен только с параметрами, переменную этого типа необходимо инициализировать явно. **Поле пользовательского класса всегда должно иметь доступный конструктор без параметров**, поскольку поля инициализируются перед входом в конструктор внешнего объекта. Это же правило рекурсивно относится к полям вложенных классов. Поле `vector<C>` инициализируется пустым вектором и не требует создания элементов `C`.

Размер значения класса определяется размерами его полей. Циклы вложения классов *непосредственно по значению* — статическая ошибка: например, `class Node { Node next; }`. Вложение через `vector<Node>` допустимо: вектор имеет фиксированный размер служебного представления, а элементы размещаются в его динамическом хранилище.

Глобальных переменных нет. Классы и глобальные функции разделяют пространство имён, доступны до объявления; взаимная рекурсия функций разрешена. Повторные объявления имени в одной области запрещены. Локальная переменная доступна после завершения своего объявления: `int x = x;` ошибочно. Локальные переменные и параметры не затеняют активные внешние локальные имена, глобальные имена или встроенные операции. Имена в независимых соседних блоках могут повторяться. К полям класса обращаются через явного получателя, поэтому параметр может иметь то же имя, что и поле.

Функции и методы не являются значениями. Аргументы позиционные, с точным совпадением типов, передаются **по значению**. Возврат класса или вектора также возвращает независимое значение. Реализация может устранять физическое копирование, только если результат наблюдаемо соответствует этим правилам.

## 4. Чтение, изменение и места хранения

Выражение может обозначать значение или существующее *место хранения* (*place*). Это различие внутреннее: отдельного пользовательского типа ссылки не появляется.

- **Чтение:** `Node x = nodes[0];` копирует элемент в `x`.
- **Запись:** `nodes[0].value = 42;` меняет поле непосредственно в элементе вектора, не создавая промежуточную копию `Node`.
- **Вызов метода:** `nodes[0].increment();` использует элемент как получателя и изменяет его на месте. Метод, вызванный на временном значении, изменяет только этот временный объект.
- **Результат функции:** `arena.get(i)` является самостоятельным значением, если `get` возвращает `Node`. Поэтому `arena.get(i).value = 42;` — статическая ошибка: слева нет изменяемого места хранения.

```egg
class Node {
    int value;

    fn increment() {
        this.value = this.value + 1;
    }
}

fn main() {
    vector<Node> nodes = vector<Node>[Node()];
    nodes[0].increment();
    Node copy = nodes[0];
    copy.value = 100;
    println(nodes[0].value); // 1
}
```

Получатель метода не копируется, если выражение обозначает место хранения; в рамках вызова `this` обозначает именно это место. Чтение `this` как значения (`Node copy = this;`, `return this;`, передача `this` аргументом) создаёт копию. `this` доступен в методах и конструкторах; присваивать всему `this` нельзя.

Порядок вычисления при присваивании: сначала вычисляются получатель и все индексы левой части слева направо, затем правая часть; каждый индекс вычисляется ровно один раз. Целевой путь к переменной/полям/элементам сохраняется как описание места хранения, **а не как потенциально инвалидируемый указатель внутрь буфера**. Границы проверяются при вычислении индекса и повторно перед записью. После вычисления правой части путь разрешается в текущем состоянии соответствующего хранилища: используется тот же числовой индекс, даже если элементы сдвинулись. Если путь больше не существует, происходит аварийное завершение с диагностикой выхода за границы; побочные эффекты правой части, выполненные до ошибки, не откатываются.

Например, в `nodes[0] = nodes.pop()` индекс `0` выбран до `pop()`. Если после удаления элемент с индексом `0` отсутствует, запись завершается ошибкой, хотя индекс был допустим до вычисления правой части. То же правило применяется к вложенным путям вроде `this.rows[i][j].value`.

### Порядок и типы операторов

| Приоритет (высокий первым) | Операции | Типы |
|---|---|---|
| 1 | `.`, `[]`, вызов `()` | По типу получателя |
| 2 | унарные `!`, `-` | `bool`, `int` |
| 3 | `* / %` | `int` |
| 4 | `+ -` | `int` |
| 5 | `< <= > >=` | Два `int` либо два `char` |
| 6 | `== !=` | Значения одного типа |
| 7 | `&&` | `bool` |
| 8 | `||` | `bool` |

Бинарная арифметика группируется слева, унарные операции — справа. Сравнения не образуют цепочек: для сравнения результатов нужны скобки, например `(a < b) == (c < d)`. `char` упорядочивается по коду ASCII (0…127).

`==` и `!=` сравнивают значения: примитивы — непосредственно, классы — рекурсивно по полям в порядке объявления, векторы — по длине и элементам. Сравниваются только значения одного типа. Таким образом, `vector<int>[1] == vector<int>[1]` истинно. Благодаря запрету рекурсивных полей по значению и отсутствию пользовательских ссылок структурное сравнение завершается на конечных значениях.

Деление усекается к нулю, остаток удовлетворяет `a = (a / b) * b + a % b`. Деление и остаток по нулю завершают программу с диагностикой. Переполнение арифметики также приводит к аварийному завершению; для `/` и `%` переполнением считается пара `MIN_INT` и `-1`. Отрицание `MIN_INT` вызывает переполнение.

Операнды, аргументы и элементы векторного литерала вычисляются слева направо. `&&` и `||` используют короткое замыкание; пропущенные выражения всё равно проверяются статически. При вызове метода сначала вычисляется получатель, затем аргументы.

## 5. Управление, функции и время жизни

Условия имеют тип `bool`. У `if`, `else`, `while` обязательны блоки; `else if` разрешён. `break` и `continue` действуют на ближайший цикл.

Отсутствующий возвращаемый тип означает `void`. `return;` допускается в `void`-функциях и конструкторах; `return expr;` — в функциях с соответствующим типом результата. Результат `void` не используется как значение. Результат вызова можно отбросить.

Для функции с результатом компилятор консервативно проверяет отсутствие достижения конца тела: `return` и отдельный оператор `exit("message");` завершают путь; `if` — если обе ветки завершают. Цикл сам по себе не доказывает завершение пути. Невыполняемые ветки тоже проходят статическую проверку.

У каждого локального значения есть время жизни: от успешной инициализации до выхода из области видимости. При обычном выходе из блока, а также при `return`, `break` и `continue` локальные значения уничтожаются; временные значения уничтожаются после использования. При `exit` или ошибке времени исполнения программа завершается немедленно; очистка через обход областей видимости не требуется. Уничтожение класса автоматически уничтожает его поля, уничтожение вектора — его элементы и динамический буфер. **В языке нет необходимости в пользовательских деструкторах для освобождения памяти значений.** Время жизни вложенных значений не зависит от того, сколько раз они копировались: каждая копия независима.

Поля и методы классов публичны. Имена членов уникальны. В классе может быть один конструктор. Если конструктор не объявлен, доступен конструктор без параметров. При `C(args)` создаётся **значение `C`**: поля по порядку объявления получают значения по умолчанию, затем выполняется конструктор. Создание значения само по себе не требует размещения в куче. Если конструктор вызывает `exit` или возникает ошибка времени исполнения, выполнение всей программы завершается.

Прямое вложение объектов в поля и хранение объектов внутри векторов не требует RC или tracing GC. Произвольные циклические структуры представляются **индексами** в отдельном хранилище (например, в арене), а не объектными ссылками.

## 6. Встроенные операции

| Операция | Результат и поведение |
|---|---|
| `print(x)` | `void`; один `int`, `bool`, `char` или `vector<char>`, без перевода строки |
| `println(x)` | То же, затем LF |
| `read_int()` | `int`; читает целую строку |
| `read_line()` | `vector<char>`; читает строку без LF/CRLF |
| `exit("message")` | Не возвращает управление; выводит текст в stderr и завершает программу с ненулевым статусом |
| `v.size` | `int`; число элементов, поле только для чтения |
| `v.empty()` | `bool` |
| `v.push(T value)` | `void`; добавляет независимую копию аргумента |
| `v.pop()` | `T`; удаляет и возвращает последний элемент как значение |
| `v.remove(int index)` | `T`; удаляет элемент со сдвигом остальных и возвращает его как значение |
| `v.clear()` | `void`; уничтожает все элементы |
| `v[int index]` | `T` при чтении; место хранения при записи/вызове метода |

`vector<char>` хранит по одному байту ASCII на элемент, поэтому его `size` — количество байтов (символов). Вывод `int` — десятичный, `bool` — `true`/`false`, `char` и `vector<char>` выводятся как байты ASCII без кавычек.

`read_int` допускает пробелы и табуляции по краям, затем необязательный `+`/`-` и одну или более десятичных цифр. Другой текст, пустая строка и выход за диапазон завершают программу с диагностикой некорректного ввода. `read_line` допускает пустую строку; последняя строка без перевода возвращается нормально. Чтение после конца потока завершает программу с диагностикой. Для `read_line` любой входной байт вне диапазона ASCII (0x00…0x7F) приводит к аварийному завершению с диагностикой; `read_int` также принимает только ASCII-символы, предусмотренные его форматом.

Индексы — `int` с нуля; отрицательный или индекс не меньше размера завершают программу с диагностикой выхода за границы. `pop()` пустого вектора завершает программу с диагностикой. Индексное присваивание заменяет существующий элемент и не увеличивает длину. `pop`/`remove` возвращают независимое значение удалённого элемента; конкретная оптимизация копирования внутри runtime ненаблюдаема.

## 7. Арены на уровне языка

Арена — **обычный пользовательский класс поверх `vector<T>`**, а не отдельный примитив ВМ. Это рекомендуемый способ построения списков и графов с индексными связями. Поскольку пользовательские обобщённые классы не предусмотрены, арену объявляют для конкретного типа узла.

Достаточно двух векторов одинаковой длины:

- `slots[i]` — значение узла;
- `next_free[i]` — `-2` для занятого слота либо индекс следующего свободного (`-1` — конец);
- `free_head` — индекс первой свободной ячейки или `-1`.

Пример реализации (корректность `release` предполагает, что индекс относится к занятому слоту этой арены):

```egg
class Node {
    int value;
    int next; // -1 означает конец списка

    constructor() {
        this.next = -1;
    }
}

class NodeArena {
    vector<Node> slots;
    vector<int> next_free;
    int free_head;

    constructor() {
        this.free_head = -1;
    }

    fn alloc(Node value) -> int {
        if (this.free_head != -1) {
            int i = this.free_head;
            this.free_head = this.next_free[i];
            this.next_free[i] = -2;
            this.slots[i] = value;
            return i;
        }
        int i = this.slots.size;
        this.slots.push(value);
        this.next_free.push(-2);
        return i;
    }

    fn release(int i) {
        this.slots[i] = Node();
        this.next_free[i] = this.free_head;
        this.free_head = i;
    }

    fn get(int i) -> Node {
        return this.slots[i];
    }

    fn set(int i, Node value) {
        this.slots[i] = value;
    }
}
```

`alloc` повторно использует свободный индекс до расширения векторов. `release` заменяет значение слота значением по умолчанию, чтобы уничтожить его прежнее содержимое, затем добавляет слот в односвязный список свободных. Управление списком свободных ячеек занимает O(1), без учёта стоимости копирования/уничтожения `Node` и возможного расширения векторов.

Индекс — обычное число. После `release(i)` старый индекс недействителен по соглашению; последующий `alloc` может снова выдать то же число уже для другого узла. Система поколений могла бы выявлять устаревшие индексы, но не требуется для этой модели арены. Поскольку поля публичны, внешний код способен нарушить инварианты арены прямым изменением `slots` или `next_free`; классы-обёртки пока обеспечивают соглашение об использовании, а не принудительную инкапсуляцию.

`get` возвращает **копию** узла. Изменить узел можно через `set`, отдельный метод арены либо непосредственно через `arena.slots[i].field = ...`. В последнем случае действует правило мест хранения из раздела 4. Копирование всей арены создаёт независимые векторы с теми же внутренними индексами; индекс сам по себе не содержит идентификатора арены.

## 8. Завершение программы и диагностика

`exit("message")` — встроенная операция аварийного завершения. Она принимает **ровно один текстовый литерал** (`TEXT`), включая пустой; вычисляемые значения типа `vector<char>` не являются допустимыми аргументами. Вызов печатает декодированный текст литерала в стандартный поток ошибок (stderr), добавляет LF и немедленно завершает процесс с ненулевым статусом. Код статуса не задаётся программой. Управление вызывающей функции не возвращается.

```egg
fn check(int x) {
    if (x < 0) {
        exit("x must be non-negative");
    }
}
```

`exit` имеет специальное правило завершения потока управления: оператор `exit("...");` считается завершающим путь при проверке функций с результатом. Сам вызов не создаёт значения, пригодного для присваивания или передачи аргументом.

Ошибки времени исполнения (индекс вне границ, `pop` пустого вектора, деление на ноль, переполнение арифметики, некорректный ввод и конец ввода) также **немедленно завершают программу** с ненулевым статусом. Runtime выводит в stderr описание причины и место возникновения (файл, строка, столбец); программно перехватить ошибку или продолжить исполнение нельзя. При нормальном завершении `main` процесс имеет нулевой статус.

Лексические, синтаксические и статические ошибки отклоняют программу до исполнения. Диагностика компилятора содержит файл, строку, столбец и причину; достаточно первой ошибки. Исчерпание памяти или иных ресурсов реализации может аварийно завершить процесс без стандартной диагностики Egg.

## 9. Пограничные примеры

| Фрагмент | Результат |
|---|---|
| `int x;` | `x == 0` |
| `Counter c;` | Создаётся отдельное значение через конструктор без параметров |
| `Counter b = a;` | Независимая копия полей `a` |
| `vector<int> y = x;` | Независимая копия элементов `x` |
| `vector<int>[1] == vector<int>[1]` | `true` |
| `vector<Node>[Node()][0].value = 3;` | Статическая ошибка: присваивание полю временного значения |
| `nodes[0].value = 3;` | Изменяется поле элемента в `nodes` |
| `nodes[0].increment();` | Метод меняет элемент в `nodes` |
| `arena.get(0).value = 3;` | Статическая ошибка: `get` возвращает значение |
| `Counter();` | Допустимый оператор создания и отбрасывания значения |
| `vector<int> x = vector<int>[];` | Пустой вектор |
| `int x = 1 + 2 * 3;` | `x == 7` |
| `bool x = true || false && false;` | `x == true` |
| `int x = 1--2;` | `x == 3` |
| `char c = 'ab';` | Ошибка литерала: два символа |
| `char c = 'Я';` | Лексическая ошибка: вне ASCII |
| `char c = '\x7F';` | Допустимо: ASCII DEL, код 127 |
| `vector<char> s = "Привет";` | Лексическая ошибка: вне ASCII |
| `fn f() { return 1; }` | Ошибка типа результата (`void`) |
| `a = b = 1;` | Ошибка синтаксиса: присваивание не выражение |
| `exit("failure");` | Печатает `failure` в stderr и завершает программу с ненулевым статусом |
| `exit(read_line());` | Статическая ошибка: требуется текстовый литерал |
